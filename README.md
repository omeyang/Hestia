# Hestia

让装修的每一个决定，都有可核验的依据。

Hestia 是面向装修新手的 AI 辅助学习与装修决策项目。它从用户指定的经验来源与限定的官方标准来源中提取信息，识别商业推广、核验时效与适用条件，形成简明、有证据、适合具体房屋的分阶段指南。

首个服务场景：**陕西西安，建筑面积 190㎡、套内面积 156㎡、完全毛坯房**。

Hestia 是希腊神话中与炉火和家庭相关的神祇，延续本账号以神话专名表达项目用途的命名习惯。[名称参考](https://www.theoi.com/Ouranios/Hestia.html)

## 项目目标

- 帮业主理解装修流程、必要决策、工艺和验收方法。
- 从指定的视频、图文与文件中提炼经验，保留原始出处及适用条件。
- 区分标准要求、实践经验、产品说明、个人偏好和 AI 推断。
- 把学习结果转化为阶段指南、问题清单、选材比较和验收清单。
- 随着标准、房屋需求和施工情况变化，更新受影响的结论与文章。

你负责指定经验来源、补充家庭需求和作出关键选择；AI 负责大部分整理、提取、对照、解释和成文工作。需要现场核查或专业设计的事项单独标明。

## 当前状态

这是项目初始版本：已有方案、房屋档案、来源边界、证据与文章模板，以及第一阶段的实施计划。

**平台采集、音视频转写、自动标准核验和文档站尚未实现。当前没有已核验的施工指导文章。**

尚未提供抖音、B站、小红书或 GitHub 装修经验链接，因此暂不导入经验内容。官方链接清单用于后续核验，不表示已经读取了标准全文或确认了每条规定适用于本房屋。

## 四类输入，各有职责

| 输入 | 用途 | 进入指南的条件 |
| --- | --- | --- |
| 视频：抖音、B站 | 案例、过程展示、施工细节、失败经验 | 指定来源；取得可处理内容；保留时间戳和必要画面证据 |
| 图文：GitHub、小红书 | 经验、清单、复盘、方案比较 | 指定文章或仓库范围；保留段落、图片或提交位置 |
| AI 自带知识 | 解释概念、整理问题、发现缺口、提出假设 | 明确标注推断；关键事实、数值和要求另有依据 |
| 标准与参考文件 | 核验要求、术语、工艺及验收依据 | 官方状态与条文定位可核验；确认适用范围和实施时间 |

来源可扩展；每个新增适配器必须输出同一套来源和证据结构。

## 基本原则

1. **指定来源不等于可信结论。** 白名单限定输入范围，结论仍需核验。
2. **先提取结论，再生成文章。** 清洗后的摘要不能替代证据。
3. **未知保留为未知。** 无法访问、转写不清、标准未找到、房屋条件缺失都必须记录。
4. **不符合要求的建议进入排除记录。** 保留理由和出处，避免再次混入指南。
5. **同源转载只算一组证据。** 多个平台重复同一说法不代表独立验证。
6. **简明与可追溯同时成立。** 正文短，依据、限制和争议通过链接展开。

## 仓库结构

- `docs/`：项目方案与决策记录。
- `profiles/`：房屋及家庭需求的结构化档案。
- `sources/`：指定来源、官方参考入口和获取状态。
- `evidence/`：证据管理约定；原始大文件放入本地 `local/`。
- `knowledge/`：待核验与已核验结论，按主题组织。
- `guides/`：面向业主的分阶段指南及清单。
- `templates/`：来源、结论与文章模板。

当前仓库公开，管理规则、处理方案、模板与适合公开的原创文章在此管理。户型图、完整报价等隐私资源未来通过云盘或 OSS 链接接入，不进入公开 Git 历史；相关适配器后续按实际需要开发。个人资料、第三方内容和标准全文的保存、再分发范围分别管理。

## 第一个可交付成果

围绕“**西安毛坯房开工前，应确认哪些条件、作出哪些决定**”，用少量指定来源跑通完整流程，交付一篇指南、一份问题清单和一份证据/争议记录。先验证方法，再扩展到选材、水电、防水等主题。
