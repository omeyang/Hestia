# 有效信息工作方法

## 前期要验证什么

先解决“指定资料能否变成有依据的有效知识”。这一阶段先跑通一个能复核、能重复的学习过程；按[飞书与 PostgreSQL 协作方案](10-online-workflow-data.md)逐步接入来源、任务与核验记录交接，两者尚未接入。云盘插件、完整平台爬虫、向量检索和文档站不作为前置条件。

处理的基本单位是独立结论。文章是结论在特定阶段和房屋条件下的表达，不是把多个摘要串起来。

视频先还原完整表达关系，再提取结论。反讽、角色对话、错误示范、情景扮演、无声图片与声画冲突的处理，以及跨视频争议和人工取舍，统一按[视频学习设计](08-video-learning-design.md)执行。

## 有效信息的判定

| 维度 | 需要回答的问题 | 未通过时的处理 |
| --- | --- | --- |
| 来源边界 | 是用户指定经验，还是限定官方核验来源？ | 未指定经验不导入，新增候选登记等待指定 |
| 内容完整性 | 实际拿到了哪些正文、声音、画面和上下文？ | 只提取可见部分，缺失关键条件时不形成确定建议 |
| 证据定位 | 可以回到具体时间戳、段落、页面或提交吗？ | 保留为待核验，不能仅引用链接标题 |
| 主张准确性 | 原文确实这样说吗？转写、数值和单位正确吗？ | 回看原始片段，疑点保持未知 |
| 时效 | 标准、产品版本与经验条件现在仍有效吗？ | 明确失效的排除，无法确认的标待核验 |
| 要求一致性 | 是否符合适用的强制要求，推荐做法有无混淆？ | 排除明确不符合的建议；争议和依据不足单列 |
| 场景适用性 | 陕西西安、本房屋及具体材料体系是否适用？ | 不适用进入记录；房屋条件缺失时列出需确认项 |
| 行动价值 | 能改变哪个决策、避免哪个错误、支持哪个检查？ | 概念解释进入参考层，重复或无关内容不进正文 |

不用一个总分代替上述判断。完整的视频也可能说错，准确的经验也可能不适用于本家；很高的“可信度分数”不能抵消关键条件缺失。

## 首轮输入方式

GitHub 可以先从问题驱动的仓库搜索发现候选，粗验后由用户指定仓库与路径，再做原文初验、获取清洗及成文。搜索方案不授予导入权限，初验不确认施工事实；具体预算、版本定位、清洗映射和 AI 交接见[统一来源管道与 GitHub 方案](09-source-pipeline-and-github.md)。这一路线可独立于视频获取推进。

用户提供少量围绕同一问题的视频；根据问题补充指定图文和必要的官方核验文件。数量先控制在足以完整检查的范围，优先完整案例、明确工艺说明和有失败条件的复盘。

每个链接依次尝试：可访问的正文/字幕 → 可获取且允许处理的媒体或页面内容 → 用户提供的文字、字幕、截图或本地文件。没有拿到内容就登记失败，不从标题或平台搜索片段推演细节。

对用户指定的 GitHub 仓库先限定相关目录和提交版本；对小红书保留图片顺序和配图文字；对短视频保留前后语境和画面展示，不能只听口播。

允许人工提供内容作为第一轮输入。自动获取只是输入方式，不决定资料能否得到严谨核验。

## 每个来源交付一张处理卡

- 内容获取范围、缺失部分及可复核位置。
- 主要问题和相关装修阶段。
- 提取出的独立结论清单。
- 推广、引流、品牌关系和排除片段。
- 错误、过时、不适用及冲突的结论。
- 需要核对的标准、厂家说明或现场条件。

这一层保留原作者的说法；不能因为总结更流畅，就把他没有说的条件和因果补进去。

视频使用[分析模板](../templates/video-analysis.md)，补充表达关系、关键画面及画面组、理解疑点和实际复核结果。对有价值的内容再形成[主题学习文章](../templates/learning-article.md)，处理卡不代替可读文章。

## 再做跨来源核验

把讨论同一问题的结论放到一起，检查是否来自同一原始内容。独立来源的案例只能增强特定条件下的经验支持，不能取代规范、测试或现场事实。

标准用于判断其实际约束的事项；厂家文件用于判断具体产品体系和施工条件；现场资料用于确认本房屋事实。文件作用不同，不能相互代替。

第一轮暂未接入厂家和现场证据时，所需信息列为缺口，不由 AI 自动扩展到新的经验来源补齐。

不同博主或同一博主前后意见不同，使用[争议记录](../templates/dispute.md)集中调查，先辨明表达与条件，再核对依据。不能因为文章要简短而删除分歧；新视频不自动覆盖旧视频。多个方案各有成立条件时转入[本家决策记录](../templates/decision.md)，提供比较与缺口，由业主确认取舍。

## AI 自带知识怎样参与

AI 可以解释术语、把问题拆开、提示常见遗漏、检索已经登记的资料、对照条件和草拟文章。

AI 提出的新说法单独标记为假设。关键技术事实、数值、条款和因果解释需要证据支持；没有找到依据时明确“不确定/待核验”。多个模型重复同一说法不算独立证据。

纯粹用于帮助理解的概念说明可以保留，但不能顺势给出缺少依据的采购规格或施工参数。

## 清洗后的内容去哪里

- 已核验且适用：进入当前阶段的建议和检查清单。
- 已核验但条件不同：保留在主题库，说明适用条件。
- 有参考价值但未核验：进入学习参考或待确认问题，明确标签。
- 互相矛盾且未解决：进入争议记录，列出所需补充证据。
- 过时、明确不符合要求或不适用：进入排除记录，保留出处和理由。
- 推广、重复、无关：记录片段处置，不进入指南正文。

“过滤”不是把问题证据删掉；排除记录也是知识资产，可以解释为什么某种热门做法没有采纳。

## 小样本验收

选定一个问题，人工回看关键原始片段，确认：主张是否忠实、数值单位是否正确、商业关系是否保留、适用条件是否丢失、引用是否支持结论。

用实际遇到的推广混合技术内容、同源转载、过时文件、互相矛盾建议和缺少房屋条件的资料检验流程。未解决的问题应正确留下，不要求 AI 为了完成文章而给出确定答案。

先交付来源分析记录、结论、主题学习文章及排除/争议记录；有足够依据后汇成阶段指南，需要取舍时记录实际决策。由这一轮暴露的问题决定后续需要自动化什么，不以文章数量或采集链接数量衡量质量。
