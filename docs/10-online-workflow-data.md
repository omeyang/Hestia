## 数据库在管道中的职责

在线数据库可以保存[五阶段管道](09-source-pipeline-and-github.md)的共享状态，让本地工具、云端工作流和 AI 处理步骤通过稳定 ID 交接。它直接服务于来源发现、抓取、清洗、核验与成文：知道哪些任务待处理、原文是什么版本、哪些结论缺证据、哪些文章需要复核。

实际抓取和分析由工具及 AI 执行。数据库保存任务、输入输出索引与判断记录，数据库中的“完成”不能代替读取原文或施工事实核验。

目标分工是：PostgreSQL 保存处理任务、版本、证据关系与核验历史，飞书多维表格展示进度并收集用户指定、审核意见和方案选择。先从小规模台账开始；数据格式继续支持 JSON、Markdown 导出，两者尚未接入时也能先跑 GitHub 小样本。

## 先确定存哪些数据

以下是逻辑记录类型，不要求第一天就建成八张表。PostgreSQL 按关系表保存，飞书按来源、进度、待核验问题与决策展示必要字段。第一轮只建立实际用到的记录。

| 记录 | 最小内容 | 帮助解决的问题 |
| --- | --- | --- |
| 候选与来源 | 稳定 ID、平台、链接、命中查询、粗验理由、用户指定记录与范围 | 搜到了什么、哪些待指定、哪些可以处理 |
| 来源版本 | 来源 ID、完整 commit SHA/平台版本、文件清单、哈希、取得范围、缺失、权利范围 | 抓到了什么、是否完整、能否复用 |
| 阶段任务与运行 | 阶段、输入版本、状态、执行者、尝试次数、错误、下次重试、输入输出索引 | 当前卡在哪里、从哪一步继续、是否重复执行 |
| 证据片段 | 片段 ID、版本 ID、原文位置、允许保存的摘录、条件、处置理由 | 清洗后仍能回到原文，解释为什么排除 |
| 独立结论 | 结论 ID、原文主张、标准化表述、类型、条件、核验状态、本家适用性 | 按问题学习与比较，避免摘要冒充结论 |
| 结论—证据关联 | 结论 ID、证据 ID、支持/反对/条件说明、同源组 | 一条结论可有多个依据，一个片段可支持多条结论 |
| 核验、争议与决策 | 核验任务、所需依据、实际定位、检查人/工具、日期、理由、未解决项及决定 | 追踪待核验工作，保留分歧和人工取舍 |
| 文章与产物索引 | 文章 ID、路径/链接、版本、引用结论、房屋档案版本、复核状态 | 汇总落地、定位受来源变化影响的内容 |

搜索查询和运行原始响应可先保存在本地批次文件，台账只记录索引。房屋档案继续以 `profiles/xian-156.json` 为准，台账引用其 ID 与 revision，不维护另一份不受控的家庭资料。

第一轮可合并候选与来源，使用 `awaiting_user_selection / selected / rejected` 区分；需要同时保留用户指定范围、获取状态、各阶段进度、结论核验和适用性。不要用一列“已验证”包含全部含义。

## 每一步怎样读写

| 阶段 | 读取 | 写入 | 下一步入口 |
| --- | --- | --- | --- |
| 搜索 | 问题、查询计划和预算 | 新候选、命中查询、响应索引与完整性 | 待粗验候选 |
| 粗验 | 候选元数据 | 继续/跳过/待确认、理由与建议范围 | 已指定范围的候选可进入初验；其他留待指定 |
| 初验 | 指定记录、固定版本与少量实际原文 | 已读定位、内容/权利检查、拟获取清单和缺口 | 通过输入检查的获取任务 |
| 清洗抓取 | 固定版本和允许路径、预算 | 来源版本、获取清单、片段映射、主张草稿、失败记录 | 具备可复核证据的结论草稿 |
| 整理汇总 | 结论、证据关联、房屋版本、限定核验资料 | 核验与争议记录、结论修订、文章索引与引用关系 | 带标签学习文章；满足准入条件的指南 |

例如，一个来源已经取得文本，但图片尚未取得：获取记录保持“部分获取”，文本可以继续分析；依赖图片才能判断的结论保持待核验。数据库应能同时表达这两个事实。

## 调度、重试与版本

先用一个串行执行器处理任务。AI 输出候选判断或结论草稿，程序检查范围和结构后写入；来源正文不能修改指定范围或核验规则。

任务身份由 `source_id + source_version + stage + input_hash + processor_version` 组成。相同身份可复用已完成产物；重试新增尝试记录，不覆盖旧错误。失败后从所需阶段继续，避免从搜索开始重做全部任务。

如果后续有多个执行器，领取任务需要原子操作，并记录 `lease_owner / lease_expires_at / attempt_id`；提交结果时核对领取者和输入版本。任务可能被重试，外部写入和最终产物都应幂等，不能假定一个任务永远只执行一次。未实测的在线表格不能直接当作具备事务锁的多执行器队列。

输出先保存并取得哈希，再将产物索引与本次成功状态提交到台账。网络中断时允许重试回写和对账，不能先写“完成”再生成文件。限流等待保存 `retry_after`，不把它误判为来源内容无效。

处理流水和核验修订保留历史。新来源版本或房屋档案 revision 变化后，通过引用关系标记受影响的结论与文章“需复核”；重新核验不会删除旧判断及理由。

## 在线台账、本地与 Git 的分工

- PostgreSQL：处理状态、任务、可公开的来源元数据、证据索引、结论修订、关联关系和待办的主记录。
- 飞书多维表格：面向用户的候选、处理进度、待核验事项、文章入口，以及用户指定和审核意见；程序维护字段由 PostgreSQL 同步。
- `local/`：原始文件、清洗全文、原始响应、大文件、登录状态与密钥。后续按授权范围需要时再接云盘/OSS，不提前实现存储适配器。
- Git：规则、模板、方案、房屋公开档案与适合公开的原创文章，以及必要的可公开索引导出。

原文全文、图片、标准文件、个人资料和完整报价不会因采用在线数据库就获得上传或公开权限。本地文件索引标注 `local_only`；其他机器可能没有该文件，读取不到时记录缺口，不能把本地路径包装成可访问的云端链接。

来源授权以 `sources/registry.json` 中的实际指定记录为准。飞书收集用户选择意向，实际指定需带确认人、日期和范围同步为可复核记录；指定记录完成登记前，不开始范围内原文初验与获取。AI 状态回写不得自行扩大白名单。

实现接入后，PostgreSQL 作为任务与运行的主记录，JSON 为导出/离线运行格式；接入前仍以本地文件为准。迁移时校验稳定 ID、数量、引用和版本。文章正文继续在 Markdown 中维护，数据库保存版本及引用索引。

## 两者如何同步

| 数据方向 | 内容 | 更新规则 |
| --- | --- | --- |
| PostgreSQL → 飞书 | 候选与来源摘要、阶段进度、失败/缺口、核验标签、文章链接 | 按稳定 ID 更新投影；这些程序维护字段不作为用户编辑入口 |
| 飞书 → 处理端 → PostgreSQL | 用户指定范围、审核意见、要求重试、实际方案选择 | 作为有身份、时间、目标版本的操作记录，校验后执行；不直接覆盖系统状态 |
| 本地/Git → PostgreSQL 与飞书 | 来源指定登记、房屋档案 revision、文章版本与引用索引 | 保留各自权威记录及版本；飞书展示引用信息 |

例如，用户在飞书指定某仓库的 `docs/` 目录，处理端记录操作 ID、确认人、范围与时间，完成来源登记后创建初验任务；执行结果写入 PostgreSQL，再把进度同步回飞书。勾选“重试”表示请求创建一次新尝试，不能直接把失败任务改成“已完成”。审核文章的表达也不自动把其中所有施工主张改成“已核验”。

飞书每条记录关联稳定业务 ID 与 `record_id`，并记录已同步 revision。用户操作关联唯一 `operation_id` 和操作所依据的版本；重复接收只处理一次。版本已变化的操作列为待重新确认，不能用最后写入覆盖新结果。

PostgreSQL 的业务更新与待同步事件在同一事务中保存，再由串行同步器更新飞书。飞书暂时不可用时保留事件并重试，处理任务可以继续；同步失败不回滚已经完成的获取或核验。首版可轮询用户操作并定期对账，事件订阅按实际 API 能力后续验证。

只同步飞书界面需要的字段，不复制完整证据库。删除飞书展示行不删除 PostgreSQL 历史；原文缺失、来源排除和文章失效通过状态表达。飞书用户编辑字段与程序维护字段分开，避免同步时覆盖尚未处理的审核意见。

**当前方向是 PostgreSQL 作为处理主库，飞书多维表格作为用户操作与查看入口。** PostgreSQL 的自管/托管方式、供应商、实例区域、飞书应用授权和字段映射仍待具体接入时决定；Supabase 仅为托管候选，不表示已选用。

在线试用前应验证本机与计划使用的云端执行器能连接同一实例，能完成少量记录读写、引用查询和导出恢复，实际套餐与额度满足需求。无需先引入向量检索；后续若发现按关键词和关系查找不足，再依据真实检索问题增加。

## 下一步怎样验证价值

沿 GitHub 路线处理一小批实际候选和指定来源，让同一来源的五阶段记录串起来。检查可以看到“为什么选它、实际读了什么、哪些没读、哪些结论待核验、引用到哪些文章”，并验证失败续跑不会丢失定位或重复生成产物。

首轮按“PostgreSQL 最小记录与导出 → 飞书展示 → 用户操作回流”的顺序接入。除查询与关联外，还应验证重复回流、旧版本操作、飞书暂时失败及恢复同步：不能重复创建任务，不能覆盖较新结果，用户意见不丢失。

抓取质量、AI 理解与施工核验另按真实原文验收，不能用数据库连通或表格中出现记录来宣称学习闭环完成。分工记录见[决策 0002](decisions/0002-workflow-data.md)。
