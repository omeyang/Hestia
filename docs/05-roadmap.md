# 实施计划

## 里程碑 0：项目基础

状态：本次初始化交付。

- 名称、定位、范围及初始技术决策。
- 西安房屋档案，已知与未知信息分开。
- 来源边界、处理流程与标准核验规则。
- 来源、独立结论和文章模板。
- 有效信息的取得、判定及小样本验收方法。
- 阶段索引、主题分层与第一篇文章范围。

方案补充：已形成[视频学习、证据核验与取舍决策设计](08-video-learning-design.md)，配套视频分析、主题学习文章、争议和决策模板。当前仅为文档设计，平台获取、声画理解、自动成文与同步尚未实现。

## 里程碑 1：小样本学习闭环

同时保留 GitHub 文本路线，避免把视频媒体取得作为所有来源学习的前置条件。[统一来源管道与 GitHub 方案](09-source-pipeline-and-github.md)已给出搜索预算、候选筛选、指定范围、固定提交与清洗规则，以及交接模板；当前仅为设计。可以先实现候选发现，再由用户指定少量仓库及路径，围绕一个实际问题形成来源分析、结论和学习文章。有足够核验与房屋资料时再汇成指南；未实际验证的图片、PDF、Issues、Wiki 与 Agent 自动编排不算已支持。

前置输入：用户指定少量视频，建议 3 条抖音视频和 1 条 B站长视频，优先覆盖开工准备；结合问题补充指定图文和必要的官方依据。尽量包含实操、图片说明及实际遇到的复杂表达或意见冲突，未覆盖类型明确列为未验证。家庭基本构成和必需家电已登记，继续补充户型图、预算范围、房间用途、长辈入住安排、具体开工与入住时间，以及设备和物业条件。

每次来源获取失败或只获得部分内容时，保留状态并改用可提供的内容；不把自动采集能力作为第一篇指南的必要前提。

交付：

- 已取得内容的来源清单与证据定位。
- 视频分析记录、关键画面定位和有价值内容的主题学习文章。
- 独立结论、商业片段标记、排除和争议记录。
- 争议问题的集中取证记录；存在真实取舍时形成实际决策记录。
- 有足够核验与房屋资料后，一篇针对本房屋的开工前指南。
- 一份集中列出未知条件、需沟通对象及决策时点的问题清单。

验收：

- 每条关键建议能回到准确的来源位置。
- 回看确认没有误解反讽、角色、错误示范或剧情，没有遗漏无声图片信息和纠正关系。
- 学习文章讲清问题与条件；理解疑点、技术核验与本家适用性分别说明。
- 重要数值和标准要求有版本、条文、单位及适用说明。
- 不混入用户未指定的经验来源。
- 保留冲突、获取失败与缺失资料，不填造确定结论。
- 区分必须核查的事项与可由业主选择的偏好。
- 业主能够据此安排下一步沟通与资料收集。

## 里程碑 2：可重复的处理工具

以第一轮实际资料为准实现最小处理脚本：来源登记、导入、定位保留、结论校验、引用关系检查和文章生成。按需要接入转写与画面识别。

处理记录包含工具/模型、提示词版本、输入哈希和运行时间。只有实际可访问并具备适当权限的平台能力才接入。控制重复转写与大文件处理成本。

按小样本结果选择浏览器自动化或 RPA、声画处理与多模态模型、Coze 或本地编排、飞书阅读与任务管理。统一中间结果及引用关系，按实际需求逐步扩展收藏批次、账号增量、B站搜索候选、集中调查和本地保存；不把这些候选工具写成已接入能力。

结构化信息先使用 JSON，文档先使用 Markdown；按[飞书与 PostgreSQL 协作方案](10-online-workflow-data.md)逐步接入处理主库、飞书展示与用户操作回流，协助阶段交接、任务重试与核验追踪，保留导出格式，当前尚未接入。全文检索辅助查找证据，检索结果仍需读取上下文；向量索引依据实际检索问题再引入。

## 里程碑 3：扩展学习与决策

按真实装修进度扩展到预算合同、系统方案、水电、防水、材料及验收。形成主题知识库、方案比较、决策记录和工程量/报价口径。

阶段清单注明前置资料和最晚决策时点。实际需要并行确定的系统与定制项目，在开工准备阶段给出关联提示。

## 里程碑 4：变化管理与现场反馈

实现来源变化、标准变化和房屋条件变化对结论/文章的影响查询，保留修订记录。现场问题、施工记录、检测和返修结果作为单独证据输入。

当前公开方案和模板；有稳定文章后再提供文档站。隐私资料的云盘/OSS链接适配、许可证和更大范围分享按实际需要处理，不作为前期有效信息闭环的前置条件。
