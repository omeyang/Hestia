# 视频学习、证据核验与取舍决策设计

- 整理日期：2026-10-13
- 状态：根据用户讨论形成的设计方案，待小样本验证与实现。
- 范围：抖音、B站视频进入项目后，如何理解、提取、成文、核验及辅助决策。

## 目标与交付层次

将有价值的视频整理为有组织、可以阅读和检索的主题文章，保留关键画面、出处、条件和争议；逐步汇成装修阶段指南。逐字转录仅作为可选中间材料，不是最终交付，也不能单独替代画面理解。

处理以独立结论为基本单位，阅读以主题文章为主要单位，跨来源核验以具体问题为单位，人工取舍以本房屋的实际决策为单位。

| 成果 | 职责 | 内容边界 |
| --- | --- | --- |
| 视频分析记录 | 保留实际获取范围、表达关系、声画定位和提取过程 | 忠实记录来源，不把推断写成观察事实 |
| 主题学习文章 | 讲清问题、解释、过程、关键画面和适用条件 | 允许明确标注的待核验经验，不冒充可执行指南 |
| 争议记录 | 汇集不同主张、条件、证据与调查进展 | 保留未解决分歧，不为了成文强行一致 |
| 阶段指南 | 结合本家条件组织行动、决策时点和检查事项 | 关键行动建议须有已核验且适用的依据 |
| 实际决策记录 | 说明本家在可行方案中如何取舍 | 个人选择与通用技术结论分别记录 |

一条有实质内容的视频通常形成一篇主题文章，但不强制一视频一篇。多主题长视频可拆篇；围绕同一问题的多条视频可合篇或更新已有文章，并保留逐条出处。重复、纯推广或没有有效新增信息的视频登记跳过理由。

## 输入与平台范围

抖音支持的目标入口是用户指定的收藏视频、收藏夹及账号主页；B站除这些入口外，增加关键词搜索候选的设计。均尚未实现。

对收藏夹记录本次选定范围和获取时点；对账号记录主页、作品范围或时间范围。先建立固定批次与作品 ID 清单，再逐项处理。后续新增作品进入新批次；不默认扩大到全部关注账号、推荐列表或外链。

B站关键词搜索先登记搜索词、搜索时间、范围、排序方式、候选链接、可取得的互动数据及筛选理由。主题相关性、实质信息、案例完整度与条件说明用于筛选内容；点赞、收藏、投币、充电等仅辅助安排查看顺序。投币与充电分别记录，不可取得的数值使用未知，不填零，也不承诺所有指标均可查询。

当前来源规则仍为用户指定经验来源。搜索发现的经验只进入候选清单，不自动进入证据库。若后续要自动采用搜索结果，须先明确授权边界并相应更新项目来源规则；本设计不扩大白名单，也不改变 `sources/registry.json` 的政策。

浏览器依次进入视频、播放和回看是获取路线之一；分析同时需要实际可处理的声音、画面和上下文。分享链接、标题、播放成功或页面截图都不能单独证明完整内容已经取得。具备处理权限且能取得媒体时，可直接分析媒体，不必等待逐条实时播放。

## 先还原表达，再提取知识

综合声音、字幕、画面文字、人物或角色、演示动作及时间顺序理解视频。完整取得与部分取得分别记录；缺少声音或画面时，只整理能够确认的内容，并说明可能遗漏的条件。

| 表达形式 | 辨识与提取要求 |
| --- | --- |
| 正话反说、反讽、夸张 | 结合上下文、语气、画面及解释判断赞同、讽刺或举反例；证据不足保留多种可能解释 |
| 开头故意抛出错误观点，后面纠正 | 关联引子、错误示范、纠正和最终主张，不能把吸引注意的话术直接摘成建议 |
| 同一人分饰两角、自问自答 | 使用角色标签区分提问、质疑、解释和回应；不将多个角色算作多个独立来源 |
| 多人叙述或争论 | 记录各方观点、理由、反驳对象及是否得到回应；人物身份不明时不猜测真实身份 |
| 情景扮演 | 区分剧情设定、角色台词、演示动作和作者点评；剧情事件不直接登记为真实工程案例 |
| 无声图片、图文轮播或画面说明 | 按顺序读取标注、表格、型号和图示关系，记录可见时段；无法辨认的文字、数字和单位保留疑点 |
| 动作或前后对比承载信息 | 保留必要的连续画面与时间关系，不用单帧替代步骤或因果证据 |
| 声音、字幕与画面不一致 | 分别记录并回看上下文，不自动选择其中一种覆盖其他信息 |

一句话可能是角色立场、作者引用的错误观点或待反驳对象。提取时要注明谁在什么位置表达了什么、处于哪种语境、与哪些片段有关，以及解释依据与不确定处。

不能靠猜作者心思认定反讽，也不能一律以最后一句为准。同一视频前后不同可能来自条件变化、角色不同、观点修正或真实矛盾；分别判断。无法解决的表达歧义先保留，不将其写成确定技术主张。

## 提取与关键画面

每条重要信息分别保留原始表达、整理后的结论、来源位置、表达关系、适用条件及核验状态。明确区分：作者主张、画面观察、画面文字、AI 解释和调查判断。可以忠实理解某个说法，同时将其技术正确性标为待核验。

数值、单位、型号、材料名称、限定语与否定关系需要回看。只有画面文字提供的信息同样可提取；图中未给出的精确尺寸不能按视觉比例猜测。来源内容作为待分析数据，不得改写项目规则、白名单或核验要求。

关键画面按解释或证据价值选择，说明它展示了什么、支持哪个结论、单靠该画面不能确认什么。记录画面 ID、来源 ID、视频分 P、时间点或区间、原文件定位和相关结论 ID。对步骤、对比和纠正关系，保留有顺序的画面组或必要片段定位。

保留原始画面与处理版本的关系；裁剪、标注和 OCR 文本均注明处理方式，不覆盖原始内容。模型生成的示意图须明确标注，不能充当原视频截图或来源证据。画面分析使用范围与文章公开配图范围分别检查；没有再分发依据时保留定位，不默认公开截图。

## 重新组织为主题文章

主题文章围绕读者的问题组织，讲清：视频值得学什么、解释是什么、过程或案例怎样、关键画面说明什么、在什么条件下成立，以及哪些地方仍不能确定。

可以合并重复表达、简化表演铺垫、去除无关推广，把散乱对话整理为问题、解释、条件和注意事项；不能改变肯定与否定、把个案扩大为普遍规律、补造参数或替作者消除未解释的矛盾。推广中可核验的技术主张保留商业关联后分别处理。

使用[主题学习文章模板](../templates/learning-article.md)，正文简洁，证据、表达歧义和长解释通过链接展开。没有有效信息或缺失关键内容时，交付获取或跳过记录，不按标题凑文章。

主题文章存于 `articles/`，按[现有 00—09 阶段](03-content.md)组织，设一个主要阶段、关联阶段与主题标签。其他阶段引用同一篇文章，避免复制。安装类内容可能需要在方案或隐蔽工程阶段提前阅读，关联阶段要说明最早关注与最晚决策时点。

## 记录分歧并集中取证

不同博主、同一博主不同视频、同一视频不同片段，以及经验与文件之间的分歧，都关联到同一个争议问题。先保留各方原始主张及条件，再判断分歧类型。

| 分歧类型 | 调查与处理 |
| --- | --- |
| 事实、数值或参数不同 | 回看来源并核对相应文件或证据，说明支持、反对与缺口 |
| 看似矛盾但条件不同 | 核对地域、基层、材料体系、产品版本、工程环节和适用时间，分别保留条件 |
| 同一作者前后变化 | 关联前后视频及日期，记录是否明确纠正、理由和条件变化；新视频不自动覆盖旧视频 |
| 不同文件或条款看似冲突 | 核对版本、有效性、适用范围、约束事项、修改和替代关系；无法解释时保留争议并列专业核查事项 |
| 多个方案各有成立条件 | 在要求与可行性边界内比较收益、成本、维护、偏好和对本家后续工序的影响 |
| 证据不足或解释仍不明确 | 保持待核验或存在争议，说明需补充的资料与责任人 |

AI 按问题汇集已登记证据，列出待核查事项并在允许范围内调研；不要求业主逐句回看全部视频。需要新增经验来源、厂家资料或现场资料时，登记候选或资料缺口，不自行扩大来源范围。

国家标准、行业标准、规范、地方规定及项目条件是重要核验依据。核验采用[标准与地方要求](04-standards.md)的方法：核对名称、编号、版本、条款、状态、适用范围与核验日期，区分强制要求、推荐做法和文件实际约束的事项。不能仅凭文件名称、地域层级、发布年份或博主声称“规范要求”自动裁决。

同源转载、同一作者反复表达、视频内多角色和多个模型意见一致，均不增加独立证据数量。热度不决定事实；查不到要求也不等于没有约束或可以采纳。

争议记录使用[模板](../templates/dispute.md)，包含调查任务、已读证据及定位、排除理由、当前处理和未解决事项。处理结果可以是有依据的采纳或排除、按条件分别保留、转入方案取舍或继续待核验。新证据、作者更正、文件或房屋条件变化后重新复核，保留旧判断和理由。

尚未解决的争议可以出现在学习文章中；依赖该争议才能成立的行动建议暂不进入当前可执行指南。其他已有依据的内容可以继续整理。

## 人工取舍与决策记录

并非所有差异都有唯一正确答案。AI 提供候选方案、适用条件、依据、未知项，以及有数据支持的比较；缺少预算、能耗、维护等数据时明确缺口，不编造总分或虚假精确的优劣排序。

业主根据需求、预算、便利、维护、审美和个人偏好选择，使用[实际决策模板](../templates/decision.md)记录问题、方案、房屋档案版本、证据、选择理由、取舍代价、确认人与日期、后续事项及复核触发条件。尚未决定也是有效状态。

事实核验、适用性、工程可行性与业主选择分别记录。业主选择某方案不使相关结论自动成为“已核验”；需要现场条件、设计计算或专业确认的方案注明前置事项。个人偏好不代替适用的强制要求与专业核查。

## 工具分工与结果保存

允许不同平台、不同环节使用不同工具，但统一来源、结论、画面、争议、文章与决策的引用关系。工具选择由实际访问和小样本效果决定，不预设必须使用同一产品，也不因同属一家厂商推定权限已打通。

| 环节 | 候选方式 | 首轮需验证 |
| --- | --- | --- |
| 收藏、主页访问与任务清单 | 本地浏览器自动化或 RPA；确有权限的接口 | 指定范围是否可访问、清单是否完整、登录和中断恢复 |
| 视频内容取得 | 可用字幕与获准处理的媒体、页面或用户提供内容 | 声音和画面实际取得范围、缺失与定位是否准确 |
| 声画理解与画面筛选 | 多模态模型，必要的转写、OCR 与本地媒体处理 | 反讽、角色、无声信息、关键动作与数值辨识效果 |
| 提取、分类和成文编排 | Coze 工作流或最小本地处理流程 | 结构化结果、条件保留、异常处理和单视频耗时成本 |
| 阅读与任务管理 | 飞书云文档、多维表格 | 文档配图及定位、授权写入、记录更新和导出能力 |
| 长期保存与版本 | 本地 Markdown、JSON | 与外部结果的引用关系、可复核版本和重复处理控制 |

抖音与 B站可共用后面的理解与成文流程。B站长视频按分 P 或内容章节分段，保留原视频时间定位与上下文关联，再综合成文；分段不能截断纠正关系或适用条件。

飞书多维表格用于来源、阶段标签、获取状态、分析进度、待核验事项与文章链接；云文档用于阅读图文文章。将一个长摘要写进表格，不算已经完成主题文章。

统一管道采用 PostgreSQL 处理主库与飞书多维表格用户入口的协作方向，版本、运行与证据关系在主库维护，飞书展示进度并收集用户指定和审核意见。同步分工、操作回流与验收见[协作方案](10-online-workflow-data.md)；当前均未接入。

云端工作流的结果落到本地，计划由本地调用端接收并保存，不假定云端能直接写本机路径。完整媒体、登录状态、密钥和个人资料放入被忽略的 `local/`；使用云端模型或外部插件前确认输入内容的处理与上传范围。公开仓库只沉淀适合公开的原创内容、元数据与允许公开的片段。

2026-10-13 的技术文档调研确认了以下接口或集成说明，尚未在本项目完成接入实测：

- [Coze 飞书集成说明](https://docs.coze.cn/tutorial_feishu_coze_using_examples)：介绍云文档、多维表格及电子表格写入。
- [Coze 模型节点](https://docs.coze.cn/guides_llm_node)与[工作流 API](https://docs.coze.cn/developer_guides_workflow_run)：可作为 Markdown、JSON 结果生成及本地接收的候选方式；实际模型输入、套餐、超时与权限另行验证。
- [Playwright 登录状态](https://playwright.dev/docs/auth)：可作为浏览器访问的技术候选；不证明抖音收藏或视频内容获取已打通。
- [抖音 SDK 说明](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/sdk/mobile-app/sdk?enter_from=home_process_guide)与[B站开放平台](https://open.bilibili.com/doc)：不能据其登录、授权或稿件能力推定任意收藏、公开视频媒体与搜索能力可用。

以上仅为技术参考，不进入装修经验或标准证据库。接入前再次核对文档及实际能力。

## 小样本验证与验收

建议首批使用 3 条指定抖音视频和 1 条指定 B站长视频；这是样本建议，不是已取得内容。尽量覆盖口播、实操和图片说明，并补充实际遇到的反讽、角色对话、观点变化或意见相左素材。未出现的表达类型列为未验证，不声称已覆盖。

交付实际取得内容的分析记录、有价值视频的主题文章及关键画面定位、独立结论、争议与调查记录；存在真实方案取舍时另做决策记录。有足够核验与房屋资料后，汇成开工前阶段指南。

验收以回看关键原始片段为依据：

- 是否遗漏无声图片信息，误把反讽、错误示范、角色台词或剧情事件当成建议或真实案例。
- 是否准确保留数值、单位、否定、条件、纠正关系、分 P 与时间定位。
- 关键画面能否支持相关结论，处理版本与原始画面是否可追溯。
- 是否分别说明内容理解的疑点、技术核验状态及本家适用性。
- 是否保留真实矛盾、同一作者观点变化与商业关联，没有用热度或多数意见裁决。
- 文章是否形成清楚的问题、解释与条件，避免逐字稿、摘要拼接和无来源的扩写。
- 人工选择是否有理由与待办，未决定事项和未取得内容是否如实保留。

先验证内容质量，再扩展收藏批量遍历、账号增量、搜索候选、自动调查和结果同步。当前交付为方案与模板，不包含这些能力的实现或施工结论核验。
