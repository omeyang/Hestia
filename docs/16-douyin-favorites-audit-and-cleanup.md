## 清理原则与本轮结果

本地 Doubao 根目录保留原始 JSON、两份分类 XLSX、更新后的项目说明；旧脚本、配套驱动和旧说明移入 `archive/20261024-legacy/`。归档清单记录原路径、现路径、文件大小及 SHA-256，并逐文件核对迁移前后哈希。恢复时根据清单移回相应位置；如目标已有同名文件，应先比对，不能覆盖。

只有替代工具验证完成且旧数据的追溯需求已结束，才考虑永久删除归档。本轮采用可恢复的移动整理，不删除原始 JSON、成果表或历史依据。

后续每轮使用“不可变原始快照 → 差异核查 → 有依据的清洗/分类记录 → 当前成果表”，所有变更按视频 URL 对齐。临时页面、驱动压缩包、失败尝试和重复导出在确认无唯一证据后再清理。批次目录保留一份原始快照、一份当前成果和一份变更记录，避免继续堆叠 `final_v2/v3`。

## 2026-10-25 收藏夹整理规则与最终结果

### 执行规则

1. **空目录才删除。** 必须实际回读目录条目为空，并确认没有后续分页；接口 `count` 为 0 或接口返回 `status_code: 0` 都不能单独作为删除依据。
2. **所有不足 10 条的目录都合并。** 规则同时适用于装修与非装修目录。合并对象必须有可解释的主题关系；可以把相关小目录合成更大的语义类目，不能只为凑够数量而无意义混合。
3. **移动必须双向核对。** 移动请求带来源目录，完成后回读目标目录与来源目录；确认目标已收录且来源已清空，才可删除来源目录。不能只凭成功状态码认定移动完成。
4. **失效与缺席分开。** 只有页面出现“视频不见了”“作者已删除”等明确失效证据，才据此取消收藏；历史清单有而当前未出现，只记录为“不在当前收藏”，不自动判定失效。
5. **作者主页绑定同一视频。** 作者名和主页必须来自同一视频条目的作者对象，不按昵称搜索或跨对象拼接。
6. **保留不同口径。** 收藏夹目录记录、页面“收藏视频”总列表和历史清单分别对账，不强行把不同口径压成同一个数字。
